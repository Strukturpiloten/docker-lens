# ADR 0046: Extend hostname owner with mandatory resolver proof v2

Status: accepted test-only implementation contract; final-source checks and native qualification pending.

## Decision

Extend existing hostname invocation 22 with four fresh IPv4/IPv6 CLI/rendered
resolver fixtures under its one original HealthRun, deadline, counters and bound
cleanup owner. Preserve all four original hostname fixtures, commands, request
literals and assertions. Register all eight slots before mutation, require global
ID uniqueness, exact HostConfig.Dns/ExtraHosts and bounded unambiguous parsed
resolver/hosts observations. Share the actual unlabelled IPv6 typed fixture with
the offline four-profile regression, independently withholding StandaloneContainer,
Command, DnsServers and ExtraHosts; native ownership labels stay separate.

Require only private schema 2/hostname-v2.json with mandatory resolver-files-v1
subsection. Preserve semantic/public hostname-v1, the exact three-key unadmitted
reader result, immediate independent reader and19-argument emitter revalidation.
No private-v1 fallback, new public schema, capability map or catalogue admission.
Use the existing private custody/publisher/reader and 16384-byte serialized limit.
Finite configured-file retention does not establish name resolution, connectivity
or IPv6 network support.

The [owning contract](../native-hostname-contract.md) records all context, fixture,
read, selected-backend, cleanup and final snapshot calls: 150/151 Podman and 152/153
Docker, upstream/Debian. Cleanup 72 calls has 737280-byte maximum capture envelope.
A checked pre-cleanup guard reserves existing cleanup envelopes and both final
ordinary reads/backend cost within original budgets; refusal still runs original
terminal cleanup. Preserve 400 calls/4 MiB,100 calls/2 MiB cleanup reserve,180 seconds,
46-second margin, existing stream/body caps and 1800-second lane watchdog. Context
acquisition retains separate existing 16-request/2 MiB/15-second bounds. Native
actual bytes and elapsed time remain conditional/unqualified until genuine runs;
summing per-call maxima is not a successful aggregate-byte guarantee.

## Changed invocation semantics and preservation

Keep all 28 invocation names/order and seven delegated cleanup scopes. Preserve
PIDs27 -> immediate strict reader -> nofile28. Invocation22 now includes resolver
failure paths and can stop the lane before PIDs. This explicitly supersedes the
old four-container invocation 22 description and any current fixed-prefix semantic
assumption in earlier checkpoint/ADR 0041/ADR 0045 prose. It does not change their
PIDs/nofile authority, prerequisites, owner scopes or immediate readers. Do not
claim that the first28 semantics are unchanged. Earlier qualification and the
frozen #147 candidate keep their original meaning and cannot qualify this source.

No per-case cleanup, new invocation/artifact/reader custody implementation, runtime/
broker framework, dependency or product API is added. Separate resolver29 remains
a separately reviewed fallback if actual combined work cannot fit without weaker
limits; this decision grants no authority to adopt it automatically.

## Verification and boundaries

Require independent source review, meaningful shared-fixture/fact withholding,
finite parsing, aggregate/cleanup/final-reserve boundary and overflow controls,
strict v2/custody/eight-ID/privacy and all-lane emitter refusal controls. Both
complete final-source gates and fresh exact-head whole-four-lane qualification
remain required. Source arithmetic, synthetic observations and old receipts do
not establish native fit or compatibility. Catalogue admission, actual BoxFerry
application acceptance and publication remain separate.

A bounded read-only saved BoxFerry source inspection found no private hostname or
public hostname-field consumer; its closed reviewed-profile catalogue inputs stay
unchanged. No new source-pair receipt is claimed or retargeted. No pin/definition,
shared workflow, dependency or Renovate extraction/ownership changes are needed.
