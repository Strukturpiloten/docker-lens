# ADR 0040: Hold runtime association in the measured PIDs source server

Status: accepted bounded preparation; original owner integration and native
qualification remain pending. No capability or canonical invocation is admitted.

## Decision

Supplement ADR 0039 with the [in-process runtime locator and source
session](../native-pids-runtime.md). Use the actual inner inspect connection's
SO_PEERPIDFD/SO_PEERCRED, retained original daemon/process/executable/namespace
objects and a bounded held-outer cgroup.procs traversal. Compare complete actual
namespace vectors to actual NS_GET_PARENT object ancestry; sibling numeric
coordinates are not matches. Return retained RuntimeBoundProcess objects
directly into the collector in that same server. Never serialize process
authority and reopen a numeric PID in another phase/process.

The original trusted Rust harness owns canonical exact-CID outer acquisition
with its original backend, actor and context. PID/start remain kernel locators,
not authentication. Expected daemon UID/executable and direct-managed-runtime
coordinate facts are independently selected from reviewed fixture facts. The
root helper may not substitute a root runtime/default lookup. Permit numeric
outer PID/start locators only from the exclusive original owner, bracketed by
that owner's actual canonical exact-CID inspections before and after root
acquisition. The implemented fixed RootBindRuntime factory validates actual
outer leader/private-init/root/namespace/outer512 custody, opens the held socket
and binds its actual daemon with a fixed version GET and independent four-lane
expectation table. It returns only pending; the original owner must complete its
second actual inspect/equality check before ConfirmRuntime. Root confirmation
rechecks the same kernel objects but does not prove the parent operations ran.
This completes the kernel factory, not the actual Rust producer or native proof.

The outer before/after/Confirm bracket must finish before experiment fixtures
are created. Only afterward may LocateBatch accept their six exact registered
CIDs; inner PID/namespace handoffs remain forbidden. The immutable context and
fixed native-pids run/slot labels corroborate actual source reads under this
trusted-bootstrap model; caller JSON, labels and helper acknowledgments alone
never authenticate a CID or construct native27 evidence. No `verified` field,
root runtime CLI, generic command broker or source-provider selector exists.

The first supported route holds/rechecks actual outer and reader user-namespace
FD identity equality. Mapped outer namespaces refuse, including rootful Podman
configured to remap; a caller boolean or Rootless=false cannot establish the
reader UID mapping. Independently selected image UID facts remain required.

Use one anonymous Unix stream socketpair on stdin through fixed sudo/Python
launch; receive exactly one mode0700 original-peer-owned directory via SCM_RIGHTS
and fixed BFPIDS1/BFREADY markers. Hold a fixed socket inode below that capture
capability; connect through its procfs FD reference with no pathname fallback.
Actual local owned-server smoke qualified that narrow kernel recipe; hosted/
native qualification remains required. Keep recvmsg throughout framing and
terminal EOF so extra ancillary rights are always detected and closed.
The received server capture capability transfers into source ownership before
endpoint/factory construction and closes before final acknowledgment. Its
original-parent counterpart remains separate. Any close uncertainty prevents
success; no borrowed descriptor number is retried after transfer.

A root-owned fixed-child watchdog establishes process-group/pidfd ownership
before work, arms child death on watchdog death, and independently handles
parent death, cancellation, TERM/KILL and reaping under the original absolute
180-second deadline. It parses no source JSON or runtime data. Seal all live
measurements by134seconds, release inner-only FDs, retain original outer/daemon
custody through the original owner's intentional inner cleanup, then check only
those retained outer objects in cleanup-only OuterFinalize. Actual EOF and all
source-handle closure precede acknowledgment; unknown cleanup never qualifies.
Legacy MeasurementSession Finish retains its original live-leaf meaning.

Clarify ownership: case27 completes six-inner/control/copy/FD cleanup, the actual
final same-actor outer inspection, source finalization/EOF and supervised exit
within its original180seconds. It deliberately retains the shared outer for
later28. Actual outer removal belongs to the original whole-lane harness EXIT
owner; successful job/aggregate and cleanup evidence, not a descriptive
outer_teardown_owner marker or helper acknowledgment, govern admission. This
amends any earlier case-local outer-removal wording without extending either
deadline or inventing successful global cleanup.

## Configured boundary and observed attribution

PID1 may already reside in an init.scope descendant. Select configured outer512
by the actual fixed guest `/sys/fs/cgroup` mount object, opened below held PID1
root, with private cgroup-namespace identity, target mount ID/device/record and
exact inode match to one held global ancestor. Select the object before checking
512; never choose the nearest512 or infer a path from CID/mountinfo root text.
Recheck its held FD/mount ID, named fixed-path reopening, original process/root/
namespaces and record through finalization. The original actor's actual before/
after runtime inspection must corroborate the private route; same-reader,
ambiguous/global-root or unqualified routes have no fallback. PID1 membership
stays unchanged; daemon/workload descendants bind to that selected root.

Collect actual held non-root ancestor max/current/hierarchical/local events,
the exact outer index, root completeness witness, fixed kernel global task/limit
observations and worker scheduler/NPROC/kernel identity. Real-root exemption
requires genuine mount binding, root `/`, actual pids availability and explicit
ENOENT for pids.max plus controller-independent cgroup.type/events, not a path
or namespace-inode guess. Keep incomplete prefixes explicit and nonpositive.
Require local-event support and actual absence of pids_localevents; otherwise
closed unsupported semantics, never guessed event propagation.

Preserve dynamic task/current endpoint pairs and derive only their observed
two-point maximum, not interval peaks/global exclusivity. Preserve nondecreasing
event pairs, require actual leaf stability and static facts, and do not attribute
unrelated ancestor hierarchical events to the owned attempt. Native acceptance
still needs actual sole-owned EAGAIN/leaf LOCAL+1, ancestor LOCAL0, headroom and
controls/reuse. Finite NPROC stays measured: reviewed kernel ordering places
NPROC/threads/scheduler/PID checks before cgroup_can_fork. Kernel release/version/
machine must match the actual worker; no file-presence/version-only admission
or blanket kernel allowlist is added. Host deadline use also requires held
outer/daemon/inner/TID time namespaces to match reader/original-parent domain.

## Accounting distinction and consequences

Supersede only ADR 0039's proposed2MiB combined physical-source/input/output cap.
Repeated mountinfo and task bindings already make that cap unsuitable for the
complete six-role source. Use a separate32MiB physical-source ceiling and65,536
read/reservations across locator, collector, HTTP and IPC input, with the existing
256-live-FD/32,768-open/64KiB-output caps. This is not a capture-budget expansion.
Sixteen conservative fixed FD reservations include bounded HTTP/control and
watchdog/launch overhead, plus the bounded Channel ancillary reservations.
All physical reservations occur before I/O and failed charges remain charged.
Precharge at most1024bytes per actual file read syscall, including partial/EOF/
error, retaining unchanged whole-file caps. Expected root absence uses bounded
metadata reservations without consuming failed FD slots. RootBindRuntime's
external_source byte/operation pair only debits the same existing source ledger
before factory I/O, including prior bootstrap costs; original-owner actual
artifact/copy receipts establish that I/O, not the JSON numbers themselves.
Final source_ledger distinguishes external/root/total and output before final
frame; all source-owned capabilities close before acknowledgment.

The parent remains400command/API units and4MiB captured output/API bodies,
300units/2MiB ordinary work and100units/2MiB cleanup. A mandatory one-way
reservation callback debits the original parent ledger before each fixed API
request. No general collector deadline changes or per-role budget resets are
allowed. Only the sealed source session can use the existing46-second cleanup
reserve. Full parent budget fit, runtime-owner integration and fresh native
qualification are still required; synthetic ledger success does not prove them.
Use a fixed32KiB inspect-body refusal cap for the six small fixture IDs;24calls
reserve786,432 captured bytes. A64KiB cap combined with the original512KiB
acquisition reserve had exhausted ordinary2MiB before helper responses and is
rejected. The tighter cap does not establish full native/parent fit or authorize
moving work into cleanup. Failed parent debits refuse before source/API I/O.
The initial version probe adds one call/4096 bytes. Without the optional Recheck,
the canonical path has18inspects+probe,19calls/593,920bytes; the Recheck superset
has24inspects+probe,25calls/790,528bytes. A closed reverse ReserveApi
frame requires the original owner debit before same-request-sequence acceptance;
the global ordinal cannot replay. The canonical transcript is29owner requests
plus19debit acknowledgments,48inputframes. The Recheck superset is30+25,55frames,
under the unchanged64cap. Both six-role16/33-task cases execute actual descriptor
IPC and retain actual source/capture ledgers under the same limits.
The actual owner debit and outer inspect operations remain required provenance,
not facts proved by accepting their protocol acknowledgments.

Tests cover actual self-procfs, real file/getdents/FD I/O over authored kernel
fixtures, namespace collisions and movement, real socketpair ancillary/framing,
same-stream HTTP lease lifetime and bounded TERM-resistant-child reaping. They
do not establish sudo policy preservation, original runtime association,
delegation/enforcement, native compatibility, OCI/birth/log attestation or
nofile28 readiness. Rootless none/v2 refusal remains nonpositive.

New literal Engine/API/UID/executable expectations are frozen reviewed-profile
facts, coupled by regression to canonical native-conformance lane/package/image
definitions, the existing reviewed exact-profile record and acquisition ceiling.
They do not install/select a new software release and are not a second operating
pin owner. Existing image/version/digest, Cargo/toolchain and Action extractions,
Renovate paths/grouping/approvals remain unchanged. Historical reviewed facts and
intentional regression fixtures stay outside automatic update streams; no second
manager applies. No dependency, operational pin, workflow, coordinator, emitter
or public API changes are made. Full final gate/native qualification remains due.
