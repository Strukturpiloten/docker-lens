# ADR 0039: Prepare a measured live PIDs boundary

Status: accepted bounded source-collector contract; unwired preparation only.
Native enforcement, mandatory PIDs27, nofile28 and capability admission remain
unproved and pending.

## Decision

Define the original measured process/controller boundary as the live objects held
after daemon startup and before releasing the PIDs workload. A future accepted
finite-enforcement observation must keep independently identified tasks in an
actual strict descendant leaf with finite16, witness actual fork EAGAIN and a
corresponding leaf enforcement event, and compare identical finite64/unlimited
controls under the actual outer512 and verified ancestor headroom. It must retain
the existing exact run/lane/backend context, aggregate budgets and cleanup owner.

This is a measured experiment window, not birth-time policy, consumed OCI,
defaults, log-source or full launch-provenance attestation. It defines that
narrower meaning explicitly; it does not adopt reserved historical ADRs
0022–0035 or claim their machinery has been delivered. ADRs 0020/0021's metadata
and unresolved destination-obligation meanings remain unchanged. It supplements
the existing original-boundary wording without relaxing PIDs27-before-nofile28.

Prepare only the closed, supervised, read-only Linux collector described in
[the contract](../native-pids-boundary.md). It holds/rechecks actual pidfd,
proc/root/namespace/controller objects (including process-root mount identity), uses actual kernel mount coordinates,
verifies strict descendant leaf identity, and accounts TIDs. Its executable has
no synthetic-source switch, arbitrary path/command, namespace entry, controller
write, rebind or authority-from-JSON API. An injectable source interface supports
hermetic tests without granting native authority.

PID/start and context fields are independent caller locators/assertions, not
container authentication. The selected trusted runtime's container-to-reader-PID
binding is deliberately still pending, as are barrier ownership, syscall effect
producer, all-ancestor attribution and strict integrated private reader. The
collector itself returns measurements and failure only, never an accepted PIDs
disposition or catalogue grant. The privileged guest, selected runtime/host and
supervising harness remain within the explicit trusted bootstrap assumption.

## Consequences and validation boundary

The collector is not wired to the canonical first26, invocation27, emitter,
product Rust API, capability maps, nofile28 or runtime launch. Rootless none/v2
refusal cannot satisfy mandatory positive four-lane PIDs27. Rootful cgroupfs/v2
is not refused merely for lacking systemd; actual measured enforcement and
headroom remain required. Metadata-compatible rootless systemd/v2 remains
unverified until actual delegation and the full experiment are established.

Use original absolute180-second terminal deadline with at least46 seconds for
cleanup, conservative local2-MiB combined source/input/output reservations,
bounded reads/FDs/output and value-free diagnostics.
SIGINT cancellation must remain value-free and fail while attempting all owned
descriptor cleanup. Recheck the no-child leaf condition around sampled reads.
No successful complete six-role budget fit or parent-accounting integration is claimed. The unchanged
parent aggregate budget remains an integration gate, not new helper allowance.

Hermetic positive/state-machine and failure controls are regression evidence,
not native execution or enforcement qualification. Complete final-candidate and
native gates remain necessary. No pins/dependencies/workflows change; therefore
Renovate extraction, grouping, approvals and ownership require no update.
