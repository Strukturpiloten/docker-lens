# ADR 0026: Mandatory supplementary-group and kernel-setting source integration

Status: accepted source integration; exact-final-candidate qualification pending.

## Context

ADR 0025 requires twenty-four canonical native invocations and complete ShmSize
validation. Its raw slice was Debian 39 capabilities/61 shapes and upstream 41/65.
ADR 0022 independently selects the reviewed lifecycle cohort at Debian 34/56 and
upstream 36/60. Historical evidence, decisions and receipts remain unchanged.
The supplementary-groups-v1 and kernel-settings-v1 source families have closed
private protocols and strict readers. Preparation and synthetic controls are not
native qualification or catalogue admission.

## Decision

Append supplementary groups as invocation 25 and kernel settings as invocation 26.
Preserve the first twenty-four calls/order, original six-child lifecycle owner
block and ShmSize one-child block byte-exact. Each new invocation gets a separate
one-child lifecycle cleanup-owner subshell. Never globally export the token or
grant it to command-clear. Existing authenticated outer teardown, one-shot cleanup
and failure propagation remain; a handoff request is not completed cleanup.

The exact-test wrapper selects each existing private library child, requires one
ignored test and passes its single once-created 180-second invocation deadline.
Existing parent/command/byte/resource/acquisition/cleanup limits do not grow or
reset. Numeric summaries and original nonzero status remain authoritative.
Cleanup-unverified or outer-handoff markers force failure despite apparent success.
Only fixed stages and the first allowlisted numeric panic location may leave the
private boundary, never panic payloads or native values.

Always run each twelve-argument CLI strict reader after its invocation, even
without public emission. Supplementary validation precedes the kernel invocation;
both precede the optional public block. Fixed direct children are
supplementary-groups-v1.json and kernel-settings-v1.json. The directory, candidate,
run, lane, Engine, rendering API, mode, package, fixture image, outer image/ID and
daemon UID come independently from the harness. Proof self-context is no oracle.

The emitter retains its nineteen-argument ABI and previous readers. Both new
readers use the independently constructed existing external context. Require an
exact closed return: correct contract string, empty list capability admission and
Boolean false catalogue admission. Integer zero is not false. No mapping/output
is permitted before complete validation.

## Consequences and gates

Private sources/protocols/registrations, catalogue, product APIs, historical
records and receipts remain unchanged. Private IDs, groups, kernel bits/defaults,
namespaces, argv, receipts, times and accounting never enter public outcomes.
Local/main/reviewed-dispatch/release consumers share native-conformance.sh. No
workflow, toolchain, downloaded-tool or image pin changes. The same candidate
separately updates the existing exact serde_json dependency to 1.0.154 for BoxFerry
consumer lock compatibility; see dependency-policy.md and the lockfile integrity
record. Existing Cargo Renovate ownership/path, extraction, grouping and approvals
remain applicable without a configuration change; historical records remain
outside operational updates. Other Lens products gain no dependency.

Literal four-profile projections and real-reader harness-tail fault injection
require both proofs and whole-output refusal. These are not native evidence.
Complete final-edit gates, independent final-diff review, fresh exact-final-candidate
26-by-four execution (104 invocations), independent evidence review, all six actual
authored-fixture volume-only rehearsals and actual Nextcloud/Supabase bind and
desired-external consumer review remain required. Later edits invalidate
qualification. No compatibility, application/full-migration acceptance, release,
publication or deployment is established here.
